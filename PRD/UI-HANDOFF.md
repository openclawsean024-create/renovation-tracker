## 2. Increment-by-increment summary

### Increment 1 — tokens & base utilities
- `index.css` rewritten from 1293 lines of `--color-*` rules to a ~960-line single source. All UI-SPEC §3 tokens added (named, not aliased). New utility classes cover skip links, eyebrow, numeric, brand row, nav row, view switch, button hierarchy (primary/quiet/icon-only/danger/disabled), modal dialog, form grid, field, form feedback, share facts, timeline grid, gantt hit/bar, board foot, stage row/list, photo empty, budget totals, empty copy, footer, status pill (back-compat), section pattern, support/section, readonly banner.

### Increment 2 — App shell & hero
- `Dashboard.tsx` header is now brand-row (left brand-mark + wordmark, right header-note with status pill + status switcher) and nav-row (Overview, Timeline, Budget, Photos, Schedule, Warranties) with `aria-current="location"` driven by an `IntersectionObserver` scroll-spy.
- Hero is `.hero` grid: `.project-intro` (title + dates + share action) and `.next-step` navy panel (eyebrow + step index + next stage + footer CTA).
- Summary is `<dl class="summary">` with 6 `.metric` cells; `.metric.completion` is the highlighted anchor with a 10-cell progressbar visualization.
- `切換工程狀態` select lives in `.header-note` so existing accessibility tests (label-based lookup) stay green.

### Increment 3 — Section pattern
- Every section is `<section class="section">` with `.section-header > .section-heading + .section-tools`.
- Stages section has the new `.view-switch` (清單 / 時間軸 tabs) with proper `role="tab"` semantics; the Gantt lives in its own dedicated section so it can scroll horizontally inside `.gantt-wrapper` only.
- Budget + Photos sit in `.records-grid` (desktop two-column, mobile one-column).
- Schedule + Warranty live inside `.section.support` as `.support-section` articles.

### Increment 4 — Read-only view
- `ReadOnlyView.tsx` mirrors the new shell/hero/summary/section pattern. `body.readonly` is toggled from `App.tsx` whenever `#share=...` is present, which makes `body.readonly .edit-control { display: none }` hide every edit affordance.
- Snapshot gantt (`readonly-gantt-row-*`) keeps its pre-polish rendering so anyone who saved a snapshot URL before the polish pass still sees the same chart. This was the cheapest way to honor "Read-only consumers do not see anything that wasn't in their snapshot" (SPEC §9.1) without rewriting the snapshot serializer.

### Increment 5 — Dialog / form / responsive / polish
- Stage/Budget/Photo forms use `<div class="form-grid">` with `.field.full` for wide controls (file, caption, note, payment status, name on stage form). Inputs/selects/textareas all use 44px `min-height`. Errors render in `.form-feedback` (success + danger variants). Top-level submit row uses `.form-actions`.
- Responsive:
  - `@media (max-width: 1199px)`: summary reflows to 3 columns; records-grid collapses; nav-row remains a single row.
  - `@media (max-width: 767px)`: header condenses, nav-row becomes a 3-column grid with highlighted current, summary reflows to 2 columns, Gantt shrinks label column to 144px, form-grid collapses to single column, all dialog actions become full-width.
  - `prefers-reduced-motion` disables all transitions and `scroll-behavior`.
  - `forced-colors` adds ButtonText borders + underline for the active nav link.
- Inline `style={{...}}` were removed from `Dashboard.tsx`, `StageForm.tsx`, `BudgetForm.tsx`, `PhotoForm.tsx`, `PhotoList.tsx`, `ReadOnlyError.tsx`, and (one trivial case) `ReadOnlyView.tsx`. The remaining `style={{}}` calls in `GanttChart.tsx` and the snapshot gantt inside `ReadOnlyView.tsx` are dynamic grid placements driven by JS-computed counts and offsets; CSS variables would not be cleaner.

## 5. Known limitations, deferred items, and unresolved questions

- **UI-009 visual QA**: the agent harness cannot drive a real browser to take screenshots at 1440×900 / 1024×768 / 390×844. The CSS is in place and the build is clean; the final visual review remains a Sean-side browser pass. If any pixel-level tweak surfaces during that pass, treat it as a follow-up polish pass with the existing tokens.
- **Inline `style={{}}` remnants**: `GanttChart.tsx` and `ReadOnlyView.tsx`'s snapshot gantt still use inline `style={{}}` for dynamic grid placement (`gridTemplateColumns`, `gridColumn`, `gridRow`, `left/width`). These are JS-computed (depend on number of days / stage offsets) and do not lend themselves to CSS-only rules; replacing them with CSS variables would be more code, not less. Per the brief, only Dashboard / ReadOnlyView / form components were in scope for the inline-style sweep; the snapshot gantt is in ReadOnlyView but the `style` attribute it carries is one trivial `<span class="gantt-bar-label">` margin (already removed).
- **`ScheduleSection` / `WarrantySection` root tags**: they are now `<article class="support-section …">` instead of `<section class="section …">`. The brief said to wrap schedule+warranty inside `.section.support > .support-section`, so two section tags nested inside one section would have produced invalid HTML. The change preserves every existing `data-testid` and ARIA label, so no test failure was introduced.
- **Stage `index` prop is optional**: `StageRow` accepts an `index` (1-based ordinal) and draws the new `.stage-number` badge when supplied. The Dashboard passes it; if another caller omits it (none exists today), the badge is hidden — non-breaking.
- **Gantt bars are now buttons** in `GanttChart.tsx`: this is intentional (the brief called for an interactive hit area with 44px minimum). The `<button>` is inert in the editable surface today (no `onClick`) but is keyboard-focusable so it satisfies UI-007 focus-visible expectations. A future ticket can wire it to open the stage edit modal.
- **The brief said "remove every inline `style={{...}}` from `Dashboard.tsx`, `ReadOnlyView.tsx`, and form components"** — all such `style={{}}` were removed except the dynamic-grid ones inside the readonly gantt, which are necessary for correctness. No new `style={{}}` was added in Dashboard.tsx or any form component.
- **`body.readonly` toggling** is implemented in `App.tsx` rather than `AppShell.tsx` to avoid touching the AppShell routing logic (which is explicitly out of scope per the brief). The class is applied on first render and re-applied on every hashchange.
