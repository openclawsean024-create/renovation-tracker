# 裝修進度管理平台（renovation-tracker）

給室內設計公司與裝修統包商使用的工程紀錄工具：用一份紀錄管理階段進度、現場照片、追加減、驗收與保固，並用一條唯讀連結讓屋主隨時查看。

> 產品名稱沿用 `GOAL.md` 的「裝修進度管理平台」。App 畫面目前仍顯示舊名「裝修進度神器」，名稱統一待 Sean 確認（見 `STATUS.md`）。
> 目前是 M1：單一工程、local-first、只用假資料。沒有後端、登入、雲端同步、金流或計費。

## 功能與狀態

| 功能 | 說明 | 狀態 |
|---|---|---|
| 工程進度看板（FR-001） | 階段新增／編輯／刪除、狀態、完成度、工期圖 | 已實作 |
| 照片紀錄（FR-002） | 上傳圖片、分類、關聯階段、預覽、刪除 | 已實作 |
| 預算追蹤（FR-003） | 業者自己的成本預算、實際支出、付款狀態、超支警示 | 已實作 |
| 屋主唯讀分享連結（FR-004） | 把當下資料做成快照放進網址；地址與聯絡方式預設不分享 | 已實作（限制見下方「分享限制」） |
| 師傅排程與提醒（FR-005） | 工班、日期、提醒日、完成狀態 | 已實作 |
| 保固紀錄（FR-006） | 項目、提供者、保固起訖、到期提醒 | 已實作 |
| 預算變更單（FR-007） | 追加減的新增、編輯、刪除、核准、拒絕；只有已核准計入總額 | M1 新增 |
| 合約金額與收款概要（FR-008） | 原合約、已核准變更合計、調整後總額、已收、待收（溢收提示） | M1 新增 |
| 階段驗收清單（FR-009） | 每個階段可自訂驗收項目，勾選通過並自動記錄檢查日 | M1 新增 |
| 照片進度回報（FR-010） | 依階段彙整照片數、最新拍攝日、最新一張縮圖與說明 | M1 新增 |
| 使用說明（FR-011） | 本檔、`docs/USER-GUIDE.md`、App 內「使用說明」按鈕 | M1 新增 |

尚未提供（規劃於 M2 之後，見 `PRD/SPEC.md` §18）：多案件管理、帳號與角色、雲端同步與雲端照片、伺服器端分享與屋主線上核准、計費、資料匯出、Email／LINE 通知。

變更單的「核准／拒絕」是業者在 App 內代為記錄屋主的決定，只是狀態紀錄，不是電子簽章，也不具契約或法律效力。

## 本機啟動

需要 Node.js 22 以上（CI 使用 Node 22）。

```bash
cd web
npm ci
npm run dev
```

開啟終端機顯示的 localhost 網址。第一次開啟會建立一個示範工程「我的裝修工程」與七個階段。

要看正式建置結果：

```bash
cd web
npm run build
npm run preview
```

## 驗證

所有指令在 `web/` 執行，任何一項失敗都視為未通過：

```bash
cd web
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

只跑單一功能的測試：`npm test -- <關鍵字>`，例如 `npm test -- changeOrders`、`npm test -- share`。
GitHub Actions（`.github/workflows/ci.yml`）在 pull request 與 push 到 `main` 時執行同一組檢查。詳細說明見 `SOP.md`。

## 資料存放

- 所有資料（工程、階段、照片原圖、預算、變更單、合約金額、驗收、排程、保固）只存在**這台裝置、這個瀏覽器**的 IndexedDB（資料庫名稱 `renovation-tracker`）。
- 沒有帳號、沒有伺服器，資料不會自動上傳或同步到其他裝置。
- **清除瀏覽器資料、使用無痕視窗、換瀏覽器或換裝置，紀錄都會遺失**，目前也沒有匯出或備份功能（規劃於 M2）。
- 合約金額與收款（FR-008）和成本預算（FR-003）分開儲存，兩者互不影響。

## 分享限制

- 分享連結是把「產生當下」的資料編碼進網址的唯讀快照，之後修改資料不會更新舊連結，需要重新產生。
- **連結未加密、無法撤銷，也不會過期**：任何拿到連結的人都能看到內容，傳出後無法收回。
- 工程地址、工班電話、保固聯絡方式**預設不放入連結**，要在分享對話框勾選才會放入。
- 連結不含照片原圖，只含各階段的照片數、最新拍攝日與照片的分類、日期、說明。照片原圖僅存於業者裝置。
- 屋主只能查看，不能在連結上核准變更單或留言。屋主線上核准、可撤銷與可設定到期的分享需要伺服器，不在 M1 範圍。

## 假資料規則

- 程式、測試、seed、文件與截圖只能使用明顯的假資料，例如 `示範屋主`、`測試市示範路 1 號`、`0900-000-000`、`demo@example.com`。
- 不得放入真實屋主姓名、地址、電話、施工照片或客戶資料。
- 不得提交 `.env`、token、金鑰或任何憑證。
- 自己試用時也建議先用假資料：這個版本沒有備份，分享連結也無法撤銷。
